## 问题一：创建/编辑弹窗点击内部即消失

### 现象

群组页点击「＋ 创建运动群」后，弹窗正常弹出；但点击弹窗内部的输入框或运动主题选择器（即"编辑"时），弹窗立即消失。
「我的」页的「编辑资料」弹窗存在完全相同的问题。

### 根因

弹窗容器写法存在事件冒泡缺陷：

```xml
<!-- 修复前 -->
<view class="modal-mask" wx:if="{{showCreate}}" bindtap="closeCreate">
  <view class="modal card" catchtap="">
```

`catchtap=""` 绑定了**空字符串事件处理器**。微信小程序中，空字符串不会注册任何有效拦截逻辑，因此点击弹窗内部元素产生的 `tap` 事件会继续向上冒泡，最终触达遮罩层 `modal-mask` 的 `bindtap="closeCreate"`，导致 `showCreate` 被置为 `false`，弹窗瞬间关闭。

这解释了"添加群组 → 点击编辑（输入框/选择器）→ 框框消失"的现象。

### 修复

将空处理器改为真实空方法 `noop()`，利用 `catchtap` 拦截冒泡：

```xml
<!-- 修复后 -->
<view class="modal-mask" wx:if="{{showCreate}}" bindtap="closeCreate">
  <view class="modal card" catchtap="noop">
```

对应 JS 中添加：

```js
noop() {},
```

### 涉及文件

| 文件 | 修改内容 |
|---|---|
| `miniprogram/pages/groups/groups.wxml` | 创建群弹窗容器 `catchtap=""` → `catchtap="noop"` |
| `miniprogram/pages/groups/groups.js` | 新增 `noop() {}` 方法 |
| `miniprogram/pages/profile/profile.wxml` | 编辑资料弹窗容器 `catchtap=""` → `catchtap="noop"` |
| `miniprogram/pages/profile/profile.js` | 新增 `noop() {}` 方法 |

## 同类问题排查与修复

对全部 WXML 做了事件绑定扫描，发现并处理了以下同类隐患：

### 1. 动态空事件绑定（group-detail 成员行）

`group-detail.wxml` 原写法：

```xml
bindtap="{{isOwner ? 'onMemberAction' : ''}}"
```

当非群主时绑定空字符串，既不触发行为又无法保证拦截，属不稳定写法。
改为固定绑定真实处理器，在方法内判断权限：

```xml
bindtap="onMemberRowTap"
```

```js
onMemberRowTap(e) {
  if (!this.data.isOwner) return
  this.onMemberAction(e)
},
```

涉及文件：`miniprogram/pages/group-detail/group-detail.wxml`、`group-detail.js`

### 2. 已确认无问题的写法（保留）

- `checkin-edit.wxml` 中 `catchtap="removeImage"`：绑定的是真实方法，正确。
- 其余页面遮罩/弹窗均无事件冒泡关闭逻辑，不涉及此问题。

## 问题三：删除未清理数据库 / 排行不显示头像 / 登录不用微信资料

### 现象

1. 解散群组或退出群组后，`group_members`、`checkins` 等数据仍残留于数据库；
2. 排行榜与成员列表中本人及他人头像不显示（因 `group_members` 中保存的是加入时的快照，之后设置的资料不更新）；
3. 登录后未默认使用微信昵称/头像，显示为「微信用户」+ 首字占位。

### 根因

1. `dismissGroup` 原实现仅将 `groups.status` 置为 `dismissed`（软删），未删除成员与打卡记录；`leaveGroup`/`removeMember` 未清理对应打卡记录；
2. 排行榜（`getGroupRanking`）与成员列表（`getGroupMembers`）直接使用 `group_members` 里的昵称/头像快照，资料过期不刷新；
3. 登录逻辑未主动获取微信资料（`wx.getUserProfile` 需用户点击授权，首次登录无该交互）。

### 修复

| 文件 | 修改 |
|---|---|
| `dismissGroup` | 解散时删除该群全部 `group_members`、`checkins`，并物理删除 `groups` 文档 |
| `leaveGroup` | 群主退出=解散（同上全删）；成员退出删除本人成员记录 + 本人在该群的打卡记录 |
| `removeMember` | 移除成员时同步删除该成员在该群的打卡记录 |
| `getGroupRanking` | 用 `users` 集合最新昵称/头像覆盖成员快照 |
| `getGroupMembers` | 同样改用 `users` 最新资料合并返回 |
| `login` | 资料变更时同步更新该用户所有 `group_members` 快照 |
| `pages/index` | 未设置头像时展示「一键设置」引导条，调用 `wx.getUserProfile` 获取微信昵称/头像（上传云存储存 fileID）并写入档案 |

### 说明

- 头像统一存为云存储 fileID（`cloud://...`），小程序 `<image>` 可直接渲染；
- 解散/退出/移除均为破坏性操作，前端已有二次确认弹窗。

### 验证

- 7 个修改文件通过 `node --check` 语法检查。
- 需重新部署云函数：`dismissGroup`、`leaveGroup`、`removeMember`、`login`、`getGroupRanking`、`getGroupMembers`。
- 需重新编译小程序前端，首页出现「一键设置」引导条，点按授权后头像昵称立即生效，排行榜/成员列表同步显示。

## 问题四：他人头像空白 / 页面加载慢 / 群信息不可修改

### 现象与根因

1. **排行榜与成员列表其他人头像空白**：头像存为云存储 `fileID`（`cloud://...`），云存储文件默认权限是「仅创建者可读写」，小程序端 `<image>` 直接渲染**他人**的 `cloud://` fileID 会因无权读取而空白。
2. **各页面加载慢**：每个页面 `onShow` 都串行执行「登录云函数（冷启动）+ 多组数据库查询」，且每次都重新查询群列表。
3. **群名称/简介不可修改**：无对应云函数与入口。

### 修复

**头像：云函数批量换取临时链接**

`getGroupRanking`、`getGroupMembers` 在返回前将成员 `cloud://` 头像 fileID 用 `cloud.getTempFileURL`（管理端，不受存储权限限制）批量转成临时 URL 覆盖 `avatarUrl`，前端即可正常显示他人头像。

**性能优化**

| 优化 | 说明 |
|---|---|
| 用户缓存 | `app.js` 将用户信息写入 `wx.setStorageSync`，页面读取时先命中缓存，跳过登录云函数冷启动 |
| 启动预热 | `onLaunch` 后台预热登录，页面 `onShow` 时已就绪 |
| 群列表缓存 | 新增 `app.getMyGroups()` 缓存群列表，`index/ranking/groups/checkin-edit` 复用；创建/加入/退出/解散/改群后 `invalidateMyGroups()` 失效重拉 |
| 并行加载 | `index` 的周概览+最近记录、`checkin-edit` 的群列表+记录、`group-detail` 的群信息+成员并行请求 |

**群信息编辑**

新增云函数 `updateGroup`（仅群主可修改名称/简介）；`group-detail` 页群主可见「编辑」按钮，弹窗修改后保存并刷新。

### 涉及文件

- 云函数：`getGroupRanking`、`getGroupMembers`（头像临时链接）、`updateGroup`（新增）
- 前端：`app.js`、`pages/index`、`pages/ranking`、`pages/groups`、`pages/checkin-edit`、`pages/group-detail`
- 文档：`README.md`（云函数更新为 14 个）

### 验证

- 9 个改动 JS 文件通过 `node --check` 语法检查。
- 需重新部署：`getGroupRanking`、`getGroupMembers`、新增 `updateGroup`，并重新编译前端。
- 注意：`getTempFileURL` 返回的临时链接有时效（约 2 小时），排行榜/成员列表每次下拉刷新会重新获取。

## 问题二：一直显示「没有加入任何群组」

### 现象

创建/加入群组成功后，群组页仍显示「还没有加入任何群组」；首页本周概览、最近打卡、我的页日历等同样空白。

### 根因

云开发数据库「仅创建者可读写」权限依赖记录内的 `_openid` 字段判定创建者。该字段**只有小程序端（客户端 SDK）写入记录时才会自动生成**；**云函数端 `add()` 写入的记录不会自动带 `_openid`**（官方文档明确：在小程序中创建的记录会带有创建者 `_openid`；云函数写入则不会）。

本项目群成员关系（`group_members`）、打卡记录（`checkins`）、用户档案（`users`）全部由云函数写入，此前未手动写入 `_openid`，导致小程序端在这些「仅创建者可读写」集合上查询时被权限规则过滤，永远查不到自己的数据——表现为「没有加入任何群组」。

### 修复

所有云函数写入时手动携带 `_openid`（即当前调用者 openid）：

| 云函数 | 集合 | 修改 |
|---|---|---|
| `login` | `users` | `users.add` 数据增加 `_openid: OPENID` |
| `createGroup` | `groups`、`group_members` | 两处 `add` 均增加 `_openid: OPENID` |
| `joinGroup` | `group_members` | `add` 增加 `_openid: OPENID` |
| `submitCheckin` | `checkins` | `add` 增加 `_openid: OPENID` |

同时更新：`database/*.init.json` 示例文档补充 `_openid` 字段；`README.md` 增加 `_openid` 说明与旧数据回填指引。

### 存量数据处理

本修复只影响修复之后新写入的数据。环境里修复前产生的旧数据（`group_members` / `checkins` 无 `_openid`）仍不可见，需二选一：
- 测试阶段：直接清空这两类数据，重新创建群/打卡；
- 保留数据：在云开发控制台对无 `_openid` 的记录批量编辑，将 `_openid` 设为该记录 `openid` 字段值。

### 验证

1. 4 个修改的云函数通过 `node --check` 语法检查。
2. 全量扫描 `cloudfunctions/**`：所有 `collection(...).add({ data: {...} })` 均包含 `_openid` 字段。
3. 重新部署上述 4 个云函数后，新建/加入群组并刷新，群组列表与打卡数据可正常显示。
